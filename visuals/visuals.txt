Stage 1 — Learn Rich

First, don't touch your Engine.

Install Rich:

pip install rich

Then make a tiny file:

test_rich.py

Learn these things in this order:

1. Console
from rich.console import Console


console = Console()


console.print("Hello Fly-In!")
2. Colors
console.print("[green]Drone OK[/green]")
console.print("[red]Move blocked[/red]")
3. Tables
from rich.table import Table


table = Table(title="Drones")


table.add_column("ID")
table.add_column("Zone")
table.add_column("Status")


table.add_row("D01", "start", "IN ZONE")
table.add_row("D02", "east", "IN TRANSIT")


console.print(table)
4. Panels
from rich.panel import Panel


console.print(
    Panel(
        "Total Drones: 20\n"
        "In Transit: 10\n"
        "Completed: 0",
        title="SUMMARY"
    )
)

Learn:

Engine
 ├── zone_stat
 ├── connection_stat
 └── drones_stat

This is where your UI becomes interesting.

For example:

len(engine.zone_stat[zone])

gives you the current number of drones in that zone.

And:

len(engine.connection_stat[connection])

gives you the number currently using that connection.

So the UI doesn't need to understand how your simulation works.

It simply asks:

"What is the current state?"

Stage 5 — Make the dashboard LIVE

This is the big step.

Right now your program does:

while True:
    self.simulation()
    time.sleep(1)

And prints things.

Instead, you want:

simulation state
       ↓
    Rich UI
       ↓
   refresh
       ↓
simulation state
       ↓
    Rich UI
       ↓
   refresh

Rich has tools for live updating.

You will eventually have something conceptually like:

with Live(render_dashboard(engine), refresh_per_second=10):
    while running:
        engine.simulation()
        time.sleep(1)

But don't copy this blindly yet.

This is the stage where you'll learn how Rich's Live display works.

The important conceptual change is:

Old
simulation
print
simulation
print
simulation
print
New
simulation
      ↓
update existing screen
      ↓
simulation
      ↓
update same screen

That's what will make your drones appear to move.

Stage 6 — Build the AIRSPACE MAP

This is probably the most challenging visual part.

Your target has:

             north ───────── east
               ╲              │
                ╲             │
                 ╲            │
                start ─────── end
                 ╱
                ╱
             west ───────── south

Your graph already knows:

zone.coordinates

So you can use the coordinates from your map.

However, Rich's normal Panel/Table widgets aren't really a graph drawing library.

So don't start by trying to make a beautiful graph.

First make:

start -------- east
  |
  |
 west -------- south

Then improve it.

You have several possible approaches later:

Option A — Unicode drawing

Use characters such as:

│
─
╱
╲
●

This is probably the most appropriate for your project.

Option B — Rich text positioning

More complicated, but gives you more control.

Option C — Another terminal graphics library

Only consider this if Rich becomes insufficient.

For your project, I'd start with Unicode + Rich.

Stage 7 — Add the event log

Your target has:

EVENT LOG


00:02:33  D07  Move start -> east       [OK]
00:02:33  D08  Move east -> south       [OK]
00:02:33  D11  Move blocked             [ZONE_FULL]
00:02:36  D07  Arrived at east          [+]
00:02:36  D15  Move east -> south       [OK]

Create something like:

self.events = deque(maxlen=10)

Then whenever something happens:

self.events.append(...)

For example:

D07 moved start -> east

or:

D11 blocked: start -> east

Your UI simply displays the last 10 events.

This is a very useful architectural idea:

The Engine produces events. The UI displays events.

Don't put Rich-specific code inside your simulation algorithm.
